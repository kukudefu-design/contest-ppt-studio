# 材料、补充提示词与制作需求

## 先读后问

列出已收到的文件、用途与来源日期；读规则、计划书、模板及参考，不将文件名或旧项目内容当作项目事实。大文件按目录和相关段落读取，图片/扫描件需视觉核对；无法读取的内容标明范围。

为事实建立轻量来源记录：`id / 结论或数据 / 原文件页码或官方URL / 日期 / 事实状态 / 可用页面`。材料中的已完成、进行中、拟开展及预期分别保留。用户陈述可作为用户提供来源，但不能谎称已获第三方核验。

发现冲突时展示具体冲突及影响。最新上传文件不必然优于同届官方规则；区分规则适用范围、时间与用户补充的事实。涉及当届规则、赛道或评分而无可靠材料时，优先查官方来源，无法核实就标明并问关键项，不编造权重。

## 按决策需要采集

已有信息不重问。会影响当前阶段的关键项优先：

| 类别 | 内容 |
|---|---|
| 比赛 | 名称、年份、赛道、阶段、受众、评审指标与要求来源 |
| 输出限制 | 时长、页数、比例、大小、语言、截止时间、匿名及标志规范 |
| 模板 | 是否强制、锁定页/母版/对象、允许修改区域、用户参考而非强制的部分 |
| 内容 | 主张、证据、项目进度、真实数据、可公开范围、需补材料 |
| 设计 | 风格是否已定、参考图、禁用内容、可编辑目标 |
| 播放 | 每次确认 PowerPoint/WPS；必要时版本、系统、是否可单击控制 |

缺页数、时长等可先做风格预览；但图中标注暂定。不能声称预览已适配未知规则或演讲时间。

## 材料缺口与可复制提示词

每条缺口写：`缺口 → 对应评审项/页面 → 为什么需要 → 需要的事实或证据 → 用户如何补充 → 未补时的处理`。区分必须用户提供的项目事实与可独立查证的公共事实；后者尽量自行核实。

补充提示词用于组织已有资料或指导用户搜集事实，不把“补齐”变成补造。示例需替换为当前项目的真实缺口：

```text
请依据我随后提供的资料，补充“试验验证方案”部分，供竞赛答辩使用。
已知：项目仍处计划阶段；尚无实测节水率。请保留这个状态。
需要组织：验证对象、对照方法、采集指标、样本与周期的确定依据、评价方法、风险及备选安排。
逐项输出：现有事实与来源 / 建议方案及理由 / 仍需我确认的内容。
不得编造已完成试验、效果数据、合作单位、奖项或样本量依据。没有资料的字段写“待补”；建议值明确标为待确认方案，不能写成实测结果。
我提供的资料：
（由用户粘贴或附上可核实内容）
```

第一阶段即输出 `gap-prompts.md`，同时给简洁缺口摘要。用户选择先预览时，不要求先把全部缺口补齐。

## 按比赛重构叙事

先做“评审要求 → 需要证明什么 → 证据 → 页”的映射，再写页纲。下面只帮助理解叙事差异，不能冒充某届官方栏目或评分：

- **大创**：研究问题、已有基础、方法与路线、创新依据、进展或验证计划、资源与进度、预期成果和风险；区分立项、中期、结项的成果状态。
- **职规**：职业目标、个人认知与职业探索、匹配证据、行动与成长、差距及调整；分辨不同赛道及阶段，不擅自补个人经历、测评和荣誉。
- **挑战杯等**：先识别实际届次和赛事类别。自然科学论文、社会调查、科技发明等的证据组织不同；不要把所有任务都改成创业商业计划，也不要混淆用户所指赛事。

每页一个主要沟通任务；可以合并、拆分、重排原文，保留事实原意。需要改变项目承诺、指标或结论时先提出建议及依据，获得确认再采用。详尽背景移入备注或附录须符合比赛限制。

## brief.md 最小内容

1. 比赛、阶段、受众、主要目标、规则来源。
2. 页数/比例/时长/大小/身份与模板等硬性限制，未确认项及影响。
3. 讲述主线、需证明的关键结论、证据状态与评审覆盖。
4. 选定风格及确认原话；文本、图表、矢量及效果的编辑标准。
5. 素材、字体、动画策略和目标播放软件。
6. 交付文件、验收方式和仍需用户处理的事项。

`storyboard.md` 按页列出：页号、角色、核心结论、来源ID、评审项、文本精简、图表/流程、素材、对象类型、动画顺序、预计讲述时间。正文总时长结合实讲与切换核验；不能仅凭字数保证时长。

风格已选且关键要求明确时，给用户一份可审阅需求摘要。明确回复可同时确认需求与继续制作；保留原话，避免追加同义确认。
