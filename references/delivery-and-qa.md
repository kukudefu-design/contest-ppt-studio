# 完整项目包与验收证据

## 交付结构

按后端实际项目结构组织，避免重复一套空目录。至少保留以下实际产物，文件名可以本地化：

```text
项目/
  exports/              最终PPTX
  preview/              风格展板和从最终PPTX生成的逐页预览
  source/               实际生成源文件、图表数据、动画配置
  assets/               使用的素材及来源清单
  brief.md              制作需求与限制、软件、验收标准
  gap-prompts.md        材料缺口与补充提示词
  storyboard.md        逐页内容、证据、对象和动作
  object-plan.json     对最终PPTX的结构断言
  qa/                  结构、视觉和播放报告
  reproduce.md         实际版本、依赖和成功运行过的命令
  state.json           当前阶段、用户选择原话和未解决事项
```

不要打包密钥、登录状态、无关私人文件或无再分发授权的字体与图库原文件。受限制资产记录获取方式与本地路径映射，讲清复现前置条件；不能因此声称完全离线复现已验证。文件路径优先项目内相对路径。

配音、演讲稿、视频不默认增加。PDF可以按用户需求附送，但静态预览必须有，不能只留最终PPTX而缺完整包记录。

## 四种检查

### 1. 内容与比赛要求

按逐页来源和评审映射核对：事实状态、数字单位、来源适用年份/赛道、遗漏指标、身份匿名、页数/比例/大小/时长及官方模板限制。实讲与点击节奏尚未测时，不保证时长刚好。

### 2. PPTX 对象与资源

使用所选后端的验证器，加本 skill 的只读检查器。按真实展示顺序盘点对象，确认正文是文本框、图表有可靠数据、每个标题字独立矢量、流程图关系可改，以及蒙版、渐变、光效是否真实保留。

运行示例（使用环境真实 Python 与 skill 根目录）：

```text
python <SKILL_DIR>/scripts/inspect_pptx.py exports/deck.pptx --output qa/inventory.json
python <SKILL_DIR>/scripts/inspect_pptx.py exports/deck.pptx --plan object-plan.json --output qa/structure.json
```

首条只做盘点，不能称“已符合全部编辑标准”。第二条把制作计划与真实对象对照。先从导出文件获取真实ID，再独立根据已批准的设计要求建立断言；不要只把检查器盘点到的对象照抄进计划来制造通过。

全套交付时每页均建立有实际内容的对象断言，覆盖正文、标题、图表及应参与动画的对象；保护页按保护规则说明。报告的 `plan_coverage` 会区分 `all_slides / partial / none / not_requested` 并列出未纳入页面。只检查某几页可以用于局部修订，但不能写成全套已验收；仅写页号的空断言也不能替代实际要求核对。

`object-plan.json` 采用以下字段，数字/ID仅为语法示例，实际必须从本项目获取：

```json
{
  "slides": [
    {
      "index": 1,
      "role": "cover",
      "required_text_shape_ids": ["2"],
      "required_vector_shape_ids": ["3", "4"],
      "required_glow_shape_ids": ["3", "4"],
      "required_entrance_shape_ids": ["2"],
      "min_native_charts": 0,
      "min_native_tables": 0
    }
  ]
}
```

- `index` 为 PPT 展示顺序的一基页码，不能按 slideN.xml 文件名猜顺序。
- 四种 `required_*` 数组为该页真实数字对象ID字符串。`required_vector_shape_ids` 检查原生自定义几何，不把 SVG 图片或文本当作逐字轮廓通过。
- 标题字符数量、字序、每字独立组、轮廓是否对应正确字形仍需人工/专用工具核对；多个路径一个字时对各原生子形状逐一断言并记录字符映射。
- `required_entrance_shape_ids` 检查进入分类的动画目标。顺序、触发、时长、延迟与视觉效果仍需后端读回和实际播放核对；静止的保护对象不强加动画断言。
- `min_native_charts` 与 `min_native_tables` 为最少数量，不证明嵌入数据正确、可以修改或格式美观；数据与编辑能力另查。

可增加顶层 `protected_parts`，键是包内路径，值是**编辑前原模板相应部件**的 SHA-256。例如把全锁定页XML、相关关系、母版、主题和固定媒体纳入。检查器只做字节级保护断言，不会自动发现全部模板依赖。同页部分可编辑时使用对象级比较与视觉对照，不能直接锁整页哈希，也不能通过删除保护断言消除失败。

该检查器仅支持常见 Transitional 命名空间；Strict 等不支持时会明确报错，不将零对象当成通过。它不做完整 Office XSD、视觉或播放验证。返回码 0 表示所请求的结构检查通过，1 为检查失败，2 为命令/输入错误；图片页会给警告，需按需求判断。

### 3. 最终文件视觉

从最终保存的 PPTX 渲染全套页面，逐页查看：字体/缺字/换行、正文溢出、遮挡、图片边缘与裁切、图表标签、对比度、留白、对齐、标题艺术字与结尾呼应。来源 HTML/SVG 的预览不能代替最终 PPTX 渲染。修复后重导出、重查受影响页面和相关对象。

### 4. 指定软件编辑与播放

在用户本次指定的 PowerPoint/WPS 中打开实际交付文件：修改一处正文、一个标题字的颜色/形状、一个图表数据项和一个流程节点；放映内容页，核对逐元素进入顺序、触发、延迟和总节奏。测试在副本上进行，交付文件保持定稿内容。

工具或用户测试结果都可作为证据，但标明谁测试、软件/版本、文件版本、范围及异常；不能把 XML 有动画、文件可打开或静态PNG正常等同于放映成功。

## 报告状态与交付措辞

每条用“通过 / 失败 / 未执行 / 不适用”，配证据、文件版本及剩余动作。若有核心缺陷，写“待完善稿”；只有目标软件实测缺失，写“待目标软件验证版”。提供具体复测操作，不用模糊的“建议自行检查”替代。

最终回复给成品、预览、完整包与报告的实际链接，并说明用户仍需做的必要操作。不承诺尚未执行的播放验证、全版本兼容或干净环境复现。
